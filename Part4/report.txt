    Using the LM Hash generator, we retrieve LM Hashes for short and simple alphanumeric passwords and try to crack them with brute force using ophcrack. This method works well for passwords under five characters, but causes the password cracker to time out for longer inputs (see Figure 1, 2, 3).

	More complex passwords require us to use rainbow tables that are provided with ophcrack. Each table represents a dictionary covering passwords and their hashes with different charsets. We were able to use the XP free small table set to crack most alphanumeric passwords shorter than 15 characters (see Figure 3c, 4b, 6c). Other tables exist for different charsets, for example, XP special for special characters.
	
	When we tested passwords containing special characters, the same results were observed, i.e. shorter passwords were deducible through brute force and longer passwords required the corresponding table set. However, these passwords took longer to resolve than alphanumeric passwords of equal length. This is likely because there is a larger set of possible passwords and hashes with an expanded charset (see Figure 8b, 9c).

	Lastly, we found that the LM Hash scheme is limited to fourteen-character-long passwords because the encryption key is based on the password, which is restricted to 64 bits since DES is used with a plaintext of KGS!+#$%. The hashing algorithm splits the password in two and concatenates the results of two separate DES encryptions under ECB mode. Additionally, the operation is case insensitive, limiting hashes to uppercase inputs. This evidently reduces the amount of work needed to calculate all possible hash combinations (~2*36^7 for alphanumeric) and makes it simple to query when using the right rainbow table. 
Password schemes that work for longer passwords or use different encryptions algorithms and block modes, would make it more challenging to design password crackers and time-consuming to retrieve results to a similar degree of success as observed with LM Hashing.
